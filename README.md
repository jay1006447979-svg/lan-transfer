# LAN Transfer 2.2

**局域网文件 / 文字传输工具。** 手机、平板、其它电脑打开浏览器就能用，**对方不用装任何 App**。

Windows 一键运行，纯 Python 标准库实现，无需 pip 安装任何依赖。

```
┌─────────────┐        同一个 Wi-Fi        ┌──────────────┐
│  电脑 (本机) │  ◄──────────────────►  │  手机 / 平板   │
│  运行 EXE    │      浏览器打开网址       │  浏览器打开    │
└─────────────┘                            └──────────────┘
```

## 特性

| | |
|---|---|
| 🚀 **大文件高速传输** | 32MB 分块 + **3~4 路并发**，请求体零拷贝直写磁盘，收尾只需一次改名 |
| 📤 **断点续传** | 断网 / 锁屏 / 关网页都能接着传，只补缺失的分块 |
| 🧠 **低内存占用** | 上传、下载、文件夹打包 ZIP 全部**流式**处理，内存恒定（1MB 缓冲） |
| 📁 **文件夹传输** | 递归上传保留目录结构；文件夹下载流式打包成标准 zip |
| 📝 **文字传输** | 收发文字、持久化历史、一键复制（含安卓 HTTP 降级）、读取剪贴板 |
| ⚡ **实时进度** | 当前速度 / 平均速度 / 剩余时间 / 可取消 / 失败明细 |
| 🎨 **好用界面** | 浅色深色自动适配、移动端友好、拖拽上传、中文文件名不乱码 |
| 🔒 **安全可控** | 路径穿越防护、`--read-only` 只读、`--token` 访问令牌 |

## 快速开始

### 方式一：下载 EXE（推荐）

到 [**Releases**](https://github.com/jay1006447979-svg/lan-transfer/releases/latest) 页面
下载 `LAN-Transfer.exe`，双击运行：

1. 窗口里会先显示**使用说明**
2. 按回车键启动服务
3. 把提示的网址（形如 `http://192.168.1.20:9876`）输入到手机浏览器

共享目录默认是 **EXE 同目录下的 `shared_files`** —— EXE 拷到哪，数据就跟到哪。

> 首次运行可能被 Windows Defender / 360 误报（PyInstaller 打包程序常见现象），
> 选择「仍要运行 / 允许」即可。

### 方式二：源码运行

```bash
git clone https://github.com/jay1006447979-svg/lan-transfer.git
cd lan-transfer
python server.py
```

需要 Python 3.8+，无第三方依赖。

## 使用说明

### 三个页签

- **文字** —— 发文字、读剪贴板、获取最新内容
- **文件** —— 上传 / 下载 / 删除文件与文件夹，查看共享文件列表
- **记录** —— 文字历史，可搜索、复制、删除

### 多设备互传

不限于"电脑 ↔ 手机"。同一个局域网内**任何**设备打开网址都能互相看到共享文件，
多方互传也行。

### 断点续传

上传大文件时如果中断（断网、锁屏、关页面、关掉浏览器），**不用从头再来**：
重新选择同一个文件，服务端会识别出已上传的分块，从断点继续。

上传进度会显示：当前速度、平均速度、剩余时间、百分比。

### 传得更快一点

程序本身已经把能省的都省了（见下方「实现要点」），剩下的瓶颈通常在外围：

| 做法 | 说明 |
|---|---|
| 走有线千兆 | 最稳，能跑满 ~110 MB/s |
| Wi-Fi 连 5GHz | 2.4GHz 实际只有 3~10 MB/s |
| 共享目录加杀软排除项 | Windows Defender 实时扫描会边写边查，大文件下能吃掉一半速度 |
| 两边别都走 Wi-Fi | 无线中继会让带宽直接减半 |

### 手机上选不了文件夹？

这是**手机浏览器的限制**，不是工具的问题。

选择文件夹依赖 HTML 的 `webkitdirectory` 属性，它只在桌面浏览器有效：

| 平台 | 选择文件夹 |
|---|---|
| Chrome / Edge / Firefox（电脑） | ✅ 支持 |
| 安卓 Chrome / 手机浏览器 | ❌ 属性被忽略 |
| iOS Safari / Chrome | ❌ 同上 |

**手机端的解决办法**：先用文件管理器把文件夹压缩成 zip 再上传，或改用「多选文件」。

## 命令行参数

```
-p, --port        端口（默认 9876，被占用会自动 +1 尝试）
-d, --dir         共享目录（默认 ./shared_files）
--bind            监听地址（默认 0.0.0.0；用 127.0.0.1 则只有本机可访问）
--token           访问令牌；设置后前端会自动带在请求里
--read-only       只读模式，禁止上传 / 删除
--no-overwrite    同名文件自动重命名，不覆盖
--open            启动后自动打开本机页面
-h, --help        查看全部参数
```

示例：

```bash
python server.py -p 8080 -d D:\share          # 换端口和目录
python server.py --read-only                  # 只让别人下载，不能传/删
python server.py --token mypass123            # 加访问令牌
python server.py --bind 127.0.0.1 --open      # 只本机用
```

## 项目结构

```
lan_transfer/
├── server.py            # 服务实现（HTTP 服务 + 内嵌前端页面）
├── launcher.py          # EXE 入口：打印使用说明、设置默认共享目录
├── LAN_Transfer.spec    # PyInstaller 打包配置
├── 启动.bat             # 源码方式的一键启动脚本
└── README.md
```

内部数据（上传会话、文字历史）存放在共享目录下的 `.lan_transfer/`：

- `index.db` — SQLite 数据库
- `chunks/` — 仅用于兼容旧版本遗留的暂存分块，v2.2 起不再写入

该目录不会出现在网页的文件列表里，打包 ZIP 时也会跳过。
超过 7 天未续传的会话会在下次启动时自动清理。

上传中的文件以 `.ltmp_<会话ID>.part` 的形式直接写在**目标目录**里（与最终文件同目录），
全部到齐后一次 `rename` 改名。这类文件同样不会出现在列表里、不会被打包。

## 实现要点

几个值得一提的技术细节：

- **按偏移直写，免合并**：分块不再落暂存目录再拼一遍，而是直接 `seek` 到
  最终文件对应偏移写入。整机实测（1GB / 32MB 片，NVMe）乱序写与顺序写同为
  ~1075 MB/s，因此并发写不会退化；收尾只剩一次 `fsync` + `rename`，
  10GB 的文件也是毫秒级完成。
- **零拷贝请求体**：分块请求体就是原始字节（`application/octet-stream`），
  服务端 `readinto` 1MB 滚动缓冲边收边写。不再经过 `cgi.FieldStorage`
  （它会先把数据写进系统临时目录、再整块读回内存），也顺带摆脱了这个
  Python 3.13 已移除的模块。
- **不做无谓的 fsync**：分块阶段不强制落盘，只在收尾刷一次。
  每 32MB 同步一次会把顺序写打成同步写，实测吃掉约一半带宽。
- **多路并发**：单条 TCP 流在 Wi-Fi 上常被丢包压住拥塞窗口，
  3~4 路并发才能压满链路（实测 1 路 280 MB/s → 4 路 697 MB/s）。
- **上传会话持久化**：会话状态存 SQLite（每线程复用一条连接），
  `/api/upload/init` 返回服务端已有的分块列表，前端据此只补缺失的分块。
- **手写流式 ZIP**：文件夹打包用 `ZIP_STORED` + 预置 CRC，本机手写 ZIP 结构，
  边读边发（`Transfer-Encoding: chunked`），内存占用与文件夹大小无关。
- **不依赖安全上下文 API**：前端不使用 `crypto.subtle` 等仅 HTTPS 可用的接口，
  因此在手机用 `http://192.168.x.x` 访问时功能完整可用。
- **路径安全**：用 `realpath` + 公共前缀校验（而非 `startswith`），
  拒绝盘符、`..`、以及内部数据目录。

## 注意事项

- 这是**局域网明文 HTTP** 工具，适合家庭 / 办公内网，**请不要在公网直接暴露**。
- 能访问该网址的人都能**查看 / 下载 / 删除**共享目录里的文件。
  敏感场景请配合 `--read-only` 或 `--token` 使用。

## 更新日志

### v2.2.0

- **大文件传输速度大幅提升**：分块改为按偏移直写目标文件的临时件，
  省掉「分块暂存 + 合并时整文件再复制一遍」的二次写盘
- **分块零拷贝**：请求体直接是二进制流，边收边落盘，不再经过
  `cgi.FieldStorage` 的系统临时文件与整块内存副本（顺带兼容 Python 3.13）
- **多路并发上传**：大文件默认 3~4 路并发，Wi-Fi 下也能压满带宽
- 分块从 16MB 提升到 32MB，摊薄每块固定开销；分块阶段不再 fsync
- SQLite 改为线程内复用连接（原来每个分块要新开 3~4 个连接）
- 修复并发上传时 `.part` 临时文件被截断导致的 `Permission denied`
- 修复出错时请求体未读完、导致 keep-alive 连接串包（`Bad request version`）
- 下载改为复用缓冲 `readinto`，减少大文件下载的对象分配

### v2.0.0

- 分块上传改为内容哈希寻址，修复大文件「缺少分块」导致传输失败的问题
- 新增断点续传：刷新 / 关浏览器 / 断网后可继续传输
- 全链路流式处理，修复大文件上传 / 打包 ZIP 时的内存暴涨
- 新增文件夹递归上传与流式 ZIP 打包下载
- 修复中文文件名乱码、文件名含特殊字符时列表无法点击
- 修复手机端上传失败（移除了仅在 HTTPS 下可用的 `crypto.subtle` 依赖）
- 新增实时速度 / 平均速度 / 剩余时间显示、单文件取消
- 新增文字历史（SQLite 持久化）、剪贴板读取
- 新增 `--read-only` / `--token` / `--no-overwrite` 等开关
- 打包为单文件 EXE，启动时显示使用说明
